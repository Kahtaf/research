The concrete remaining fixture work is small:

1. Admit a stable post-fix BOOT/raw revision independently, retaining its hash/identity. Extract its real ramdisk, preserve actual init, use the retained entropy adapter and fresh diagnostic seed. Reuse the runtime kernel above rather than the mount-only c59e kernel.
2. Solve **both** fstab mappings. Actual ramdisk `fstab.mt8163` and SYSTEM `/vendor/etc/fstab.mt8163` both use `/dev/block/platform/soc/11230000.mmc/by-name/{system,userdata}`. The prior fixture maps SYSTEM to `/dev/block/vdb` and data to `/dev/block/vda`; changing only ramdisk fstab leaves late `mount_all` waiting on physical userdata. A narrowly reviewed disposable COW top layer over the read-only actual raw can carry the vendor fstab mapping and diagnostic service/import without copying the whole raw. This layer has not been implemented or qualified here; enumerate its file changes before execution and label its runtime result as adapted.
3. Create **fresh** 512 MiB legacy ext4 data using the prior `source/run.py` profile; do not touch old data images or original userdata. Installed CAPEX ZIP metadata gives 27 decompressed packages totaling 227577856 bytes, so 512 MiB is a reasonable bounded first service-chain backend, not a general Android capacity qualification. Stop/report ENOSPC if encountered. Keep original crypto/APEX waits, actual policy, properties, service ELFs, APEX packages and core init actions intact.
4. First attempt: one vCPU, 1 GiB guest, no NIC/USB, 64 MiB single-thread TCG cache, 2.5 GiB process address space and 90-second wall timeout, matching the retained fixture. Observe genuine first/second-stage init with enforcing SELinux, platform self-tests, bootstrap runtime APEX activation/linker namespaces, early_hal Keymaster4 and keystore2, then actual post-data apexd and `keystore.module_hash.sent`. Use real Binder/HIDL registration/functional IPC; add a small crypto request only after registration. Record the first actual fatal error or timeout without skipping it or setting readiness properties. QEMU exit 0 alone is not acceptance.
