# Independent offline review of future phase-bound recovery proofs

Decision: **ACCEPT the bounded source optimization for the inspected fixed-graph contract; HOLD final future-image integration and every physical/flash/timing decision.** No reachable ordinary concurrent p10 writer was found in the inspected fixed init/proxy/daemon/helper/policy graph. The new checks preserve the existing five actual byte-hash samples and the stop/freeze state machine. This conclusion depends on that graph excluding writers; it does not turn metadata into content proof.

Two precision findings below need to accompany any use of the proposal. Neither demonstrates a reachable production source regression under the fixed graph. The existing two-role helper versus future five-role manifest gap is a separate integration blocker, already acknowledged upstream. No source, helper, policy or approval was relaxed by this review.

## Priority findings and minimal changes

**P2 — qualify the persistent-mutation guarantee at the final sampling boundary.** `snapshot/REPORT.md`, failure table and source-consistency prose, and `snapshot/HANDOFF.json` describe persistent unexpected content mutation as refusing verification/commit. This is true only when changed bytes are read by a subsequent full proof. In `source/recovery_phase.h:23–28`, node checks before/after `fd_hash` establish binding, not current bytes. `source/rescue.c:150–151` performs no later content sample between the commit hash and successful commit send.

Independent deterministic witness: during the fifth p10 hash, the fixture performs the ordinary-file `pread` into the hash buffer, then changes the same inode's first byte before returning that read. All metadata remains valid. The hash sees the pinned old bytes; the daemon sends the commit receipt and clears uncertainty, while the actual fixture p10 remains changed. A change after the full hash and before send has the same limitation. This is outside the writer invariant and is inherent to sampling; the baseline also has no post-final-sample content observation. It is not evidence that the optimization admits an ordinary concurrent writer.

Minimal fix: state that persistent changes **observed by a later full proof** refuse that boundary; the no-writer invariant must hold throughout hash reads and through the terminal receipt. Retain both the upstream midphase delayed-detection witness and this final-sample witness. If that invariant is unavailable, hold the optimization and resolve the real writer; another metadata check or readiness flag cannot repair the guarantee. Do not claim every unexpected persistent change necessarily prevents commit.

**P3 — narrow descriptor-replacement language.** `source/recovery_phase.h:14–20` binds stat identity and validates path/label/geometry, but does not check access flags or `FD_CLOEXEC`, nor can stat prove the identity of an open file description. The upstream failure table's unqualified “held FD replacement/closure” refusal is too broad.

Independent witness: after a valid activation, open the same fake p10 inode with `O_RDWR`, `dup2` it over the guard fd, and close the spare descriptor. `recovery_phase_chunk` accepts it; the replacement is writable and `dup2` cleared close-on-exec. The existing different-inode/closed-fd witnesses still refuse. The production code opens the guard `O_RDONLY|O_CLOEXEC`, contains no concurrent fd-table mutator, and closes it before the only descriptor shuffle. Thus no ordinary reachable substitution was found.

Minimal fix: document detection of closed fds and replacements that change the checked binding, together with the source-based no-fd-rebinding assumption. If access-mode/close-on-exec enforcement is desired, add explicit `F_GETFL`/`F_GETFD` checks in a separately reviewed source change; these still cannot detect an equivalent same-node read-only replacement. No helper or production source was changed here.

**P1 integration blocker, separate from the optimization — existing helper cannot admit five roles.** `source/handoff.h:4` requires exactly two roles and no uncertain image. The unchanged helper independently requires `image_count==2` and the exact stock manifest digest before opening p10. A five-role model passing ordinary daemon tests does not make this helper compatible. A changed core also changes the prior-container binding required by the helper. Minimal continuation requirement: separately specify and review compatible final core/helper/manifest bindings and original-pair prerequisites. Preserve all current refusals until that work exists. Never change `2` to `5`, bypass the stock digest, weaken original-pair proofs or weaken prior-container proof merely to make integration pass.

## Why the reachable-writer premise is supported, and its limits

The exact saved `init.rc` has three services: stock init acting as ueventd, `os-rescue --serve` (root, explicit domain, oneshot), and fixed proxy launching authenticated adbd. The config hashes match the receipt-pinned core inventory. There are no imports, updater/recovery services, shell service, partition mounts, fstab or exec actions. The inventory's `/system/bin/sh` has the same binary digest as the fixed proxy; it is not a general shell. The proxy source accepts only `-c rescue-v1` with UID/EUID2000, shell domain, Enforcing and non-TTY I/O, or its fixed adbd launch path. It forwards bytes, not executable commands or passed file descriptors.

The read-only effective-policy query was inspected and rerun against the exact binary policy using the vendored local libsepol. It uses `sepol_compute_av`, expanded type attributes and MLS, not textual rule matching. Among init, ueventd, adbd, shell, os_rescue and p10_restore, only p10_restore has recovery write, and none has generic block or whole-disk write. Only os_rescue can transition to the helper and execute its entrypoint from the ordinary graph. Shell/adbd cannot use daemon/helper fds or ptrace those processes. The new daemon/helper types inherit no broad attributes or capabilities/fork permission. Independent assertions additionally check actor permissive bits, capability2 and the exact BLKGETSIZE64 extended ioctl grants.

Init has significant capabilities and node relabel authority; ueventd can create/unlink/set attributes on nodes. Policy alone is therefore not the exclusion proof. The fixed config contains no action that relabels recovery to another writable type, and fixed ueventd uses the pinned labels and node rules. Per-chunk target and p10 fd/path/alias/geometry/holder/mount guards remain necessary. Source fixes targets to BOOT/SYSTEM and conditionally DATA; `open_part` refuses ordinary recovery/whole-disk writable opens. Every admitted target fd is checked for the expected production block major/minor, label and geometry. Ordinary requests cannot supply arbitrary paths or descriptor numbers.

The daemon binds the abstract lifetime writer lock before accepting connections and processes sessions serially. The only p10 writer is entered at opcode0x30 in session IDLE with no uncertainty and verified stock SYSTEM/BOOT. The new guard is closed first. Handoff duplicates all original descriptors above the reserved slots before assigning 3/4/5, preserving the lock even when original fd numbers collide. It does not fork. A duplication failure before slot replacement closes copies and ends that request without starting a helper; any slot/exec failure afterward exits74. Successful exec replaces the daemon, so the ordinary accept loop cannot coexist with the helper.

The unchanged helper checks peer/domain/UID, inherited lock, RAM-only state, exact two-role stock manifest, original pair and fixed prior container. Its only writable p10 open is the fixed exclusive restore transaction, with unchanged full prefix/prior-suffix transition proofs, fsync/readback and final full hash. It then closes the writable fd and serves only terminal observation while retaining the lock. Failure/death is not success; no code resumes ordinary RSC after helper exec. Init's oneshot configuration supplies no automatic ordinary-daemon restart. The lock is cooperative exclusion among these exact programs, not a kernel write lock against arbitrary privileged processes.

This is a source-and-public-evidence conclusion for the supplied fixed graph. Stock init/adbd executable behavior and authenticated boundary are adopted from their pinned parent evidence, not newly reverse engineered or physically exercised. The future revised executable/image does not yet exist, so this review cannot certify its exact runtime policy, labels, fd inheritance or binary/source correspondence. A future final RAM image must reestablish the premise against its **final** init, all executables, loaded policy including expanded actors/permissive/transition/ioctl permissions, labels and aliases, manifest, geometry, helper binding and service lifetime. Added services, shells, permissions, alias writers or a restart path invalidate transfer of this result.

## Byte proof, state and error analysis

All five full recovery hashes remain on the held fd: before target reconciliation; after the scan; at activation; after whole-target hash before VERIFIED; and at commit before its receipt. Each revised full proof checks its p10 binding both before and after actual byte hashing. Activation binds manifest/pin/image/fresh reconciliation token; WRITE/SKIP checks that binding, identity and the target fd before current-chunk read. Client content hashes, current-target hashes, false-SKIP rejection, write/fsync/readback, whole-target proof, prerequisites and deliberate inverse constraints are unchanged. There is no fallback reopening or reuse of a failed guard.

The guard is session-stack state, initially fd=-1, and is closed on ordinary exits, partial-frame/disconnect/error paths and before handoff. It is neither journaled nor reconstructed from STATUS. The global uncertain image/pin survives connection failure, requiring explicit same-image or admitted inverse reconciliation and a fresh token. UNCERTAIN is set before opening the target writable; failures publishing UNCERTAIN or VERIFIED cannot acknowledge successful progression. Failed verification/commit sends keep mutation frozen. An accepted kernel send can clear daemon uncertainty even when the host loses its receipt; host UNKNOWN remains mandatory. These are unchanged distinctions, not durability supplied by the new guard.

Unexpected same-node mutation after an acknowledged chunk can allow subsequent valid WRITE/SKIP acknowledgements; the next full proof refuses if its read observes the changed bytes. A transient mutation restored before the next full proof can escape detection. Binding checks also sample node/alias/metadata state; they are not continuous watches. An already-held target fd does not redirect when its pathname changes. No new unconditional immutability, arbitrary-root protection, security improvement or continuous-content guarantee follows.
