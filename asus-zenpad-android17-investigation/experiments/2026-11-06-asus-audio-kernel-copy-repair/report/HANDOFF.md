# Future parent input: DL1/UL1 callback repair

**Completed:** a real three-file kernel source patch, genuine affected-object ARM64 compilation, exact-production-body ASan/UBSan behavior tests, preserved original negative reproductions, source/header/compiler receipts, and patch application verification. **Not completed or claimed:** full kernel link, product integration, boot, physical sound, microphone qualification, or runtime/physical GO.

The source investigation corrects the prior ledger: Linux4.9 `.copy` is a0/negative-error **status** callback, not a short-frame-count callback. ALSA treats every nonnegative return as success for the whole requested chunk. The inherited driver therefore falsely accepted truncated and failed copies. The patch removes transfer rounding, uses negotiated frame bytes/position, rejects malformed/insufficient rings and overflowing requests, and commits accounting only after a complete successful user transfer. Playback user faults do not mutate DMA memory. Capture faults or post-copy errors may leave a changed user buffer, but do not consume those bytes or report them accepted. Hardware progress is separately accounted.

The pointer/copy/IRQ lock mismatch is fixed within the two PCM files by using the existing IRQ ring lock. The helper stages data outside user-copy spinlocks, uses per-direction sleeping mutexes for copies and buffer lifetime operations, and rejects stale commits after stop. Normal DMA deltas are retained under the common lock. See CONTRACT.md and REVIEW.md for exact source reasoning and limits.
