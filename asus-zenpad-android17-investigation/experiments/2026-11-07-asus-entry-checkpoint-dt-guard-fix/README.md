## Admission contract

The parser uses only x4–x17 and NZCV, reads x0, and leaves x1–x3, x18–x30 and SP untouched. It uses no call, stack, heap, C runtime, or mutable global. All literal references use the kernel's existing `adr_l` macro. Refusal falls through before any retained store.

The initial read is limited to a 40-byte header inside pinned RAM. Magic, version 17, compatible-version 16/17, and total size 40 bytes through 2 MiB are checked. Structure and string offsets/sizes are read as exact big-endian u32 values, widened to x registers before addition. Structure alignment is four bytes, memreserve alignment eight bytes, physical FDT alignment eight bytes. Header, structure, strings, and the complete terminated memreserve map must be bounded and nonoverlapping; arbitrary order of the latter blocks is supported. Every memreserve pair checks u64 addition overflow and refuses intersection with the retained writer. A zero-sized nonzero-address memreserve entry is refused as ambiguous with the Linux reader's terminator convention.

Every token advances within the admitted structure block. Node names and property names have bounded NUL scans; property name offsets are checked against the admitted string block, including their terminator. Tokens, balanced nodes, one empty root, nonempty child names without '/', properties before child nodes, depth at most 32, and a final END token at the exact structure end are required. There is no raw signature/pattern search. Unrelated property values, including `/chosen/bootargs` and both chosen initrd values, are skipped using their checked length only.

Root compatible must be a complete, nonempty, NUL-terminated string list containing `asus,p00a`. Root cells must be 2/2. Exactly one root memory node (`memory` or `memory@...`) must have `device_type="memory"` and the exact bank `[0x40000000,0xbd600000)`. Additional memory nodes and memory-type aliases at other paths refuse. `linux,usable-memory`, if present on that memory node, must describe the same bank, since Linux otherwise prefers it over `reg`.

Exactly one root `reserved-memory` node must have 2/2 cells and empty `ranges`. Direct reservation children may reorder their properties and may use multiple fixed reg tuples when they do not intersect the retained region. All fixed reg pairs check u64 overflow. Exactly one tuple must intersect `[0x44400000,0x44480000)`, and that child's entire reg must be exactly `0x44400000 + 0x80000`. Its compatible value is exactly `mediatek,ram_console\0`; `no-map` and `reusable` must be absent; status must be absent, `ok\0`, or `okay\0`. Any other intersection refuses, including disabled reservations or memreserve aliases. Duplicate critical properties, duplicate memory/reserved roots, duplicate reservation child names, and nested reservations refuse. Child-name uniqueness uses a rescan of the already validated reserved-memory prefix; this is finite under the same structure bounds and uses no saved stack. Its worst-case cost is quadratic in reservation child count.

Runtime physical FDT, linked `_text.._end`, retained writer and the **pinned reporter payload range `[0x44000000,0x4403f007)`** remain inside the admitted RAM bank. FDT/kernel/initrd/retained conflicts are refused before writing. Initrd exclusion deliberately uses that pinned actual load range, independently of runtime chosen metadata; it does not assume chosen was authoritative. No UART, watchdog, timer, exception-level setup, security policy, MMU/cache state, scalar variant, or cache flush was introduced.

## Local verification and limits

Run from this spike with `sh scripts/check-local.sh`. This performs one standalone assembly with local Apple clang targeting `aarch64-none-elf`, then runs the already-local camera fixture Python environment with Unicorn, Capstone and pyelftools. It installs nothing and accesses no network, cloud, device, or private payload. The driver relocates the actual ELF object and executes its bytes; CurrentEL and SCTLR read results are explicitly supplied by the harness. The harness `_end` is a synthetic kernel extent. These are unit checks, not a full linked-kernel ABI proof or physical proof.

The 32 focused cases cover original DT admission; ordinary changed bootargs plus harmless 32-to-64-bit chosen initrd cell representation; reordered critical paths/properties/string offsets; compatible list membership; status ok/okay; missing/wrong/competing/duplicate reservations; flags/status/compatible refusals; fake critical properties at another path; memory aliases/usable-memory override; malformed sizes/offsets/overlaps; and unchanged MMU/cache/OEM refusal. Every refusal produces zero retained stores. Positive runs preserve platform/reason bytes, publish the full tag before the sole nonzero commit, and preserve required registers/SP. The final commit remains `str w17,[x4,#0x38]; dsb sy`. One added malformed-input case exposed an unterminated `device_type="memory"` alias borrowing its NUL from padding. The corrected parser refuses it; the [failing fixture](qa/failure-unterminated-memory-type-alias.dtb), [original failure record](qa/failure.json), [pre-fix object](qa/before-memory-nul-fix.o), and [output](qa/before-memory-nul-fix.stderr) are retained. All 32 final cases pass. Failure DT/output capture remains in the driver for reproducibility. Assembly stderr is empty. The first patch-application check found BSD patch kept the deleted include as an empty file without `-E`; [the failure record](qa/patch-apply-first-failure.txt) is retained. Applying with `-E` removes it and matches the delivered sources exactly. A single object was rebuilt while completing the source correction; no full kernel build occurred.
