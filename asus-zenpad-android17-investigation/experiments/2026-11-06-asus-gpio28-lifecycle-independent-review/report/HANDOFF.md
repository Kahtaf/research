The lock review covers the complete codec/amp/gate lock graph in the supplied selected source, plus pinned ALSA/GPIO/pinctrl/devres boundaries. [Exact lock/API bodies and locations](../evidence/lock-source-bodies.c) and [their hashes](../evidence/lock-source-receipts.json) support these conclusions:

- Codec init/remove take `codec_registration_mutex` before the state mutex. Control registration runs with the writer mutex held and the state mutex released. The codec's state critical sections never acquire the registration mutex.
- ALSA user reads hold the card power lock then read `controls_rwsem`; user writes take its write side before entering the callback. Both then enter state. Actual `snd_soc_add_codec_controls` reaches `snd_ctl_add`'s write lock, so keeping registration outside state is necessary. Removal does not register controls while holding state. Platform unregister executes after releasing state, avoiding recursive entry through codec removal and avoiding state-before-core-client-lock nesting.
- Guarded analog controls nest state before `Ana_Ctrl_Mutex` or `Ana_Power_Mutex`; analog clock helpers can then acquire `Ana_Clk_Mutex`. Unguarded speaker-mode and conditional mic-bias controls use their existing analog mutexes without subsequently entering state. `Ana_buf_Ctrl_Mutex` code is inside `#if 0`; the AW spinlock path is excluded in the selected preprocessing. No reverse analog-to-state call was identified.
- Codec paths into `AudDrv_GPIO_EXTHPAMP_Select` nest state (and, where present, analog control) before `aud_amp_mutex`. The actual GPIO headset callback now acquires state before amp and invokes `UpdateHeadsetGainLocked` at both existing gain-before/after-apply positions. `AudDrv_GPIO_Headset_Boost` does not reacquire amp; known gain readers and headset-state updates are serialized by state. Amp-only select helpers do not call the public locking gain entry. This avoids both the prior potential amp-to-state inversion and recursive state/amp acquisition.
- Gate operations nest state before `p00a_gate_lock`; cache writes/private mirrors and free occur under state. The lock may nest GPIO request/direction and pinctrl service locks. Pinned gpiolib drops its `gpio_lock` around the chip request callback. Pinctrl GPIO request/direction holds its controller mutex while calling lower MTK operations, with no codec-state callback in those bodies. Devres releases its spinlock before invoking release callbacks; `p00a_gate_release` can therefore acquire state. Immediate `devm_add_action_or_reset` execution is outside state, verified by the error-window test.

The fixture checks real mutex ownership and selected framework lock ordering; it does not instantiate all kernel lock classes. Internals of unprovided PMIC/register/clock helpers, callers outside the pinned corpus, kernel scheduling and full ASoC/DAPM lockdep remain outside the bounded conclusion. No claim of a whole-kernel lockdep proof is made.

Readiness and suspend state now have distinct lifetimes. State protects the private pointer and readiness through allocation, defaults, publication, access, clearing and free. Persistent `mAnaSuspend` is written only by the explicit PM entry, including while absent. Gate acquisition inherits it; successful codec initialization reconciles it before releasing state. `mAnalogSuspendApplied` is reset per allocation, so old backups cannot be restored into a new private instance. Repeated suspend synchronizes the gate interlock without falsely resaving an old backup. Only explicit resume clears intent; resume does not automatically assert the external gate. Allocation failure, registration windows, failed gate acquisition and action-reset windows preserve that policy in the additional tests. No separate numeric generation token is needed for these serialized private accesses: neither audited readers nor callbacks retain an allocation pointer past the mutex boundary. Same-device platform/devres lifetime remains framework-owned.
