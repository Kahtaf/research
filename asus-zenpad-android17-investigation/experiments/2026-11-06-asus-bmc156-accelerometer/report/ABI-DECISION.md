# ABI decision — before implementation

Choose OEM BMC156 register/data code adapted to the existing Linux4.9 `sensors-1.0` core, plus a new accelerometer-only C sensors HAL API1.3 loaded by the genuine SDK37 HIDL1.0 wrapper. The inspected wrapper explicitly requires C API>=1.3. Its installed module will be `sensors.mt8163` with only libc dependencies, not the stock binary.

The rejected evdev alternative needs the old core as well as the stock HAL, whose public ARM32 ELF imports liblog/libcutils/libutils/libc++/libdl/libc/libm and enumerates other legacy nodes. Its input_event protocol cannot decode the 4.9 packed 36-byte sensor_event (int64 boot timestamp; four int8 fields; six int32 words). Keeping the current core and implementing one ABI is the smaller bounded path. Stock ELF pin: 012f8cbb24eb0af15c0163e164fe5e67e1031c80d8d710983016872f1ce9408c. Interfaces are captured in evidence/interfaces*.txt.

The exact ASUS GPL `bmc156_acc.c` (d3a43a00419e7c1096e1b216ae665a57a69e7af3ab0ff363240e4aed14a9a609) calls its internals BMA255. Retain its chip-ID check, register sequence, signed12 decode, +/-4g range, 512 counts/g, and direction4 (-X,+Y,-Z). Do not substitute the existing BMA253 driver. Board remains I2C2/0x11, no controllable external LDO (power_id=0xffff); chip NORMAL/SUSPEND writes remain real. Existing DT is preserved.

Port registration to the real4.9 batch/flush/set_cali callbacks and device PM API. Remove unused factory/DMA/debug/legacy ioctl and kernel file-I/O surfaces. Add checked raw-count calibration transfer through the existing acccali callback; the HAL privately reads only the future reviewed /data/vendor/sensors/p00a/gs_cali.ini. OEM file is 14 bytes: signed LE32 triples scaled128, marker0xaa, alternating add/xor checksum. OEM reader ignores checksum and returns no error on missing file; it is invoked only by factory atd_caligs, not normal initialization. Source HAL deliberately rejects malformed present files; absent calibration remains explicit UNRELIABLE operation with no synthetic calibration record or write. HWMON_ACC's 12-byte payload is a related public schema, not permission to reinterpret its container or apply both calibrations.

The core timestamps are CLOCK_BOOTTIME nanoseconds; XYZ words are mm/s² (OEM gravity9807 and divisor1000). HAL preserves board axes and divides by1000 exactly once. Remove core interpolation of repeated samples; report only actual successful reads, including zero vectors and -1 components. Non-wakeup continuous accelerometer only, no FIFO, no fusion/compass/ALS/gyro, no injection/direct channels. Flush completion must be queued after preceding actual samples. Errors must reach callers.

Physical runtime, real calibration consumption, full product SELinux/VINTF/linker qualification, gravity/axes/rate/rotation and suspend remain parent-owned and unproved.

Final inspection also pins the ARM64 stock sensor ELF (0d0fb39fb1a7b8f59dc67ea2617f60052441610d7012dc8925f2b16c695ed652), with the same seven dependency names as ARM32; see evidence/public-stock-sensor-elfs.json. SDK37 SensorDevice and HidlSensorHalWrapper retain the actual fallback to HIDL1.0, independently confirming that the wrapper source is reachable by the framework. Final rate limits are10–200ms, retaining the stock100Hz descriptor maximum; actual rate accuracy still needs physical measurement.
