## Preconditions and exact interfaces

- A newly parent-combined full kernel/DT and a full SDK37 product that passed actual ELF, init, SELinux and VINTF checks. The current staged relocatable sensor object is not a bootable Image.
- Boot/probe identity: `bmc156_acc` binds `mediatek,gsensor`, adapter2/address0x11. OEM chip-ID read is register0x00 and expected value0xfa. The driver validates the `mediatek,bmc156_acc` board metadata: bus2, address0x11, direction4, no external controllable power rail (`0xffff`, represented as `-1` by the4.9 helper), FIR0, batchingfalse.
- Device: `/dev/m_acc_misc`, dynamically allocated sensor character-device major, minor0. This is **not evdev**. Do not run a concurrent raw reader while the HAL owns this global queue.
- Class path: `/sys/class/sensor/m_acc_misc`; source-derived real path `/sys/devices/virtual/sensor/m_acc_misc`. Verify real symlink resolution and labels on the booted candidate. Expected labels: `p00a_accel_device` on the node, `p00a_accel_sysfs` on the directory, `p00a_accel_control_sysfs` on exactly accactive/accbatch/accflush/acccali.
- HAL-owned controls: accactive receives ASCII `0\n` or `1\n`; accbatch receives `0,0,<period_ns>,0\n`, accepted periods10,000,000–200,000,000ns; accflush receives `0\n`. acccali accepts exactly12 little-endian raw-count bytes **only from the private, validated restoration path while disabled**. Do not inject calibration bytes from this document or tests.
- Data: packed36-byte little-endian sensor_event, timestamp signed64 at0, kernel handle0 at8, action0=data/1=flush at9, status at10, reservedzero at11, XYZ int32 at12/16/20, remaining wordszero. Data are board-coordinate mm/s², boot-time nanoseconds; HAL reports handle1, dividesXYZ by1000 once and preserves timestamp. Flush marker has zero timestamp/status/words.
- Framework service: `android.hardware.sensors@1.0::ISensors/default`, ARM64 process, source C API1.3 module `sensors.mt8163`. No `/vendor/etc/sensors/hals.conf`; wrapper must take its single-module path. Only accelerometer appears in getSensorsList and the feature XML.

## Observations needed to qualify hardware

1. **Probe and permissions:** parent captures public-only kernel driver/probe errors, node type/minor and path/SELinux metadata, successful HAL registration and an accelerometer-only sensor list. No calibration payload, factory values or private identifier dump is requested. A failed ID/I²C read must fail probe; no fake sensor node/return substitution is permitted. If `/dev/m_acc_misc` is absent, the HAL returns open failure.
2. **Calibration consumption:** parent privately verifies original14-byte file integrity and destination metadata, then records only restored/absent/malformed status and whether HAL accepted it. No broad NVRAM access. A valid read exercises acccali and medium status; absent data produce unreliable status; malformed present data must stop open. This is still not a physical accuracy test.
3. **Gravity and six orientations:** through the framework SensorManager accelerometer stream, observe a stationary norm near Earth gravity and the expected signs on ±X/±Y/±Z. Check the actual tablet's screen axes against direction4 (-chipX,+chipY,-chipZ). Do not silently change the transform to make one pose look right; establish panel/tablet coordinate convention first.
4. **Rates, state and flush:** request10,20,50,100,200ms periods, measure boot-time interval distributions, monotonicity and elapsed time across a rate change. Verify enable→samples, disable→no subsequent samples, repeatedenable stability, invalid handles, flush-after-active and pending-flush ordering. No FIFO latency guarantee is advertised; positive maximum latency results in immediate reporting. Confirm actual ODR/read timing; only register writes and software cadence are compiled/model-proved here.
5. **Framework rotation:** verify the Android17 framework consumes this accelerometer for application auto-rotation where enabled. No magnetometer, orientation/fusion sensor or gyro is exposed or required by this stage. An injected packet test does not prove auto-rotation.
6. **Suspend/resume and repeated service restart:** parent observes chip SUSPEND/NORMAL transitions, preservation of requested enable/rate/calibration, no stale/backfilled samples, boot-time continuity and recovery. This non-wakeup accelerometer does not request waking the device. The SDK37 wrapper takes a fatal path if a non-message-queue HIDL1.0 service dies; service restart testing must account for framework recovery rather than assume seamless reconnection. Also verify close/disable and failure paths on the real controller, without unbinding this built-in driver (bind/unbind sysfs controls are suppressed because the existing core has no safe unregister callback).

These observations are blockers for a **working-hardware claim**, not unfinished source-port placeholders. The source/ABI staging does not depend on a private-value upload. No compass0x13, ALS0x1e, camera, radio, charging, framebuffer, root or Google Play change is included.
