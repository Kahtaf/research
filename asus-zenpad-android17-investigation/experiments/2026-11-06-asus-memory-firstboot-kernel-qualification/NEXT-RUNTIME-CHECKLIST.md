# Consume a future capture in a fresh fixture

This checklist is preparation only. No future capture was read, copied or prepared by this qualification.

1. Obtain the capture owner's terminal qualified native-build receipt, exact reviewed r8 profile and complete coherent manifest. Reject failed-build receipts, the old r7 profile and partial input groups.
2. Pin the c59e Image/config and this acceptance. Use a new owned input/run revision; preserve every old run. Verify source/copy/before/after hashes and actual ELF implementations/dependency closure.
3. Admit official platform self-tests32/64, signed runtime/bootstrap APEX bytes with actual contents and trust metadata, generated properties/apexkeys, and the matching complete policy/CIL/context/VINTF/init/fstab group. Host /apex symlinks do not supply package contents.
4. Retain genuine crypto/APEX waits and their fatal failures. Let actual hwservicemanager, apexd and keystore own their readiness/module-hash handoffs. Keep observers read-only; do not forge boot/BPF readiness.
5. Requalify enforcing init, manager IPC and negative controls with c59e. Require actual crypto/APEX/namespace/Keymaster/keystore evidence before each downstream claim; a normal fatal reboot with QEMU exit0 is a failure.
6. If lmkd is included, review the exact zram0 context candidate in the new coherent set, preserve intended low-RAM inputs, and verify real lz4/swapon/PSI/EPOLLPRI/properties/SID. A 1GiB service fixture is not the earlier stock-RAM test. Keep the four eligible-cycle passes and protected-overload failure distinct.
7. Save consumed hashes, command, raw serial and terminal status. Keep full Android/GMS working-set, hardware, root/authentication and physical GO gates false until separately proved.
