## Findings, in priority order

### F1 — High: no usable 4.9 host observation/acceptance profile is supplied

`O/source/observer.py:16–17,37–53` accepts diagnostic serial `0123456789ABCDEF` and marker `os-rescue-v1`. The actual artifact writes USB serial **P00A49PROBE** (`B/probe/init.rc:24`) and reports **ASUS RAM-only diagnostic combined-linux49-r1** (`B/probe/diag.c:96`). A synthetically correct new-probe inventory at the pinned physical port is rejected as `Unexpected device at physical port`. `B/scripts/observe.py` observes build processes; it is not a device observer.

`../2026-11-06-asus-recovery-control-wifi/source/recovery_control.py:123–168` deliberately requires the exact stock wrapped kernel, including `parsed['kernel'] == original['kernel']` at line 160. That refusal is correct and must remain. The old orchestration observer also has old markers and serial-only selection; it is not a substitute.

**Minimal fix:** parent supplies a separate narrow 4.9 profile and validator binding the exact image, compiled compressed Image, three-property DT delta, header, ramdisk, policy/helper/public-key identities and full padding. Use `P00A49PROBE`, the exact report marker, expected ADB product/model/device, physical topology and the exact current `transport_id` on every targeted call. USB product string `P00A_RAM_49_probe` is not the ADB model: `default.prop` still yields `P00A_RAM_diagnostic`. Do not loosen the stock-only writer. A proposed non-authorizing contract is supplied in `proposed-acceptance-contract.json`.

**Evidence/reproduction:** `python3 -B scripts/observer_faults.py` replaces all subprocess execution with an in-memory stub; `evidence/observer-faults.json` records the rejection. No ADB executable runs.

### F2 — High: the inherited observer can exit successfully without a valid report, and does not enforce pin freshness

`O/source/observer.py:90–96` returns normally when stock identity/boot-completed checks pass, even with `report_ok == false`. The reproduction supplies report exit 74 / `open errno=13`, then the expected stock identity: main returns normally with `stock_returned=true`, `report_complete=false`, `recovery_restored=false`. Thus process exit 0 must not mean diagnostic acceptance or inverse-write verification.

`observer.py:37–41` calls the pin “Fresh” but checks neither its age nor a binding to a current preflight/run. The synthetic year-2000 pin passes. `validate_report` at lines 56–59 uses substring checks; a suffixed wrong serial, enforcing `0`, and a battery read error all pass when the old expected marker is present. These are inherited defects that a marker-only 4.9 adaptation would retain; the unmodified observer already rejects the new marker under F1.

**Minimal fix:** separate typed outcomes for `report_collected`, `diagnostic_requirements_passed`, `stock_returned`, and `stock_recovery_readback_verified`. Require the intended conjunction before overall success. Bind the topology pin to the same fresh, exact-stock preflight and parent run; reject stale/missing bindings, ambiguity, transport failures and changed topology. Parse the serial as an exact token from the unique `/proc/cmdline` section, never an arbitrary substring. Preserve the existing explicit `-t` selection. Stock return is an observation, not proof that p10 was restored.

**Evidence:** `evidence/observer-faults.json` and `evidence/observer-simulation/events.jsonl` (entirely synthetic).

### F3 — Medium, acceptance-blocking if ignored: a completed report can contain failed or silently missing observations

`B/probe/diag.c:104` ignores every `section()` result. `directory()` at lines 62–82 silently exits on getdents failure and does not record its four-buffer cap or malformed records. `collect():112–116` writes `END_DIAGNOSTIC`, publishes, and returns 0 unless output/publication fails. The report endpoint reports successful file transport, not successful measurements.

Independent ASan/UBSan fault injection reproduced all of: every read returning EIO; `/proc/cmdline` denied; enforcing read as `0`; battery uevent returning EIO; and getdents returning EIO. Every scenario returned 0, published once, and included END. The last scenario recorded no read/open error at all. The supplied test already expressly expects collection success on failed reads (`B/probe/test_diag.c:109–110`), so a passing test count does not refute this finding. The enforcing-zero scenario tests collection semantics; the separate adbd-launch guard would refuse an initially permissive launch.

**Minimal fix:** for r2, the new host validator must distinguish partial evidence from passing diagnostics and require explicit successful identity/enforcing/kernel/USB sections; unavailable hardware sections must be marked unavailable, not ready. For a later candidate, retain partial evidence but add a structured collection result and per-directory error/truncation status. Repackage and re-review any changed image. Do not count marker/END alone as hardware readiness. `/sys/class/power_supply/battery/uevent` also does not expose `charge_guard`'s disable/error/age telemetry; r2 cannot certify the charging guard's complete runtime state. A later bounded guard read could improve that evidence, after pinning its actual sysfs path and labels.

**Evidence/reproduction:** `source/fault_collection.c`, `evidence/collector-faults.txt`. All Linux syscalls are mocked; no device or reboot path exists in that executable.

## Early boot, electrical activity and recovery limits

The radio Kbuild adds `MTK_WCN_REMOVE_KERNEL_MODULE` and the built-in entry points. `K/drivers/misc/mediatek/connectivity/p00a/bootstrap.c:107–121` only registers root-only `/dev/wmtdetect`; the actual WMT/STP/BT/WLAN initialization is deferred to the guarded `DO_MODULE_INIT` ioctl at lines 65–83. The diagnostic has no caller, firmware mount or launcher. Real linked WMT/STP/WLAN symbols do not mean RF was activated. Existing connectivity platform/reserved-memory plumbing remains; this is not proof of electrical radio-off measured on hardware.

Charging is **software-inhibited by default**, not physically proven off. `K/drivers/misc/mediatek/power/mt8163/asus_p00a/bq25896.c:144–208` reads identity, checks a disable, configures routing GPIOs and programs safe limits; `policy.h:109` requires the absent `charging_permitted` flag before enabling. `control.h:381–470` reaches its sole charge-enable operation only after that policy. SOC startup disables charging before its initial sample (`K/drivers/power/supply/mediatek/battery/asus_p00a_soc.inc:247`). No alternate enable route was found in the reviewed combined path.

Nevertheless this is not electrically passive: monitor/source detection writes BQ/PMIC registers, ADC/BATON reads include hardware transactions, and BC1.2 uses USB PHY clock/control (`bc12.inc:46–118`, `usb20/mt8163/usb20_phy.c:603–621`) even without charging permission. A failed I2C probe or disable cannot prove inherited charger state is off. A battery sysfs read can itself request a disable on an I/O error (`battery_status.inc:45–56`). The helper's “no peripheral control” text describes its direct syscalls, not every driver-side effect of a read. Default charging-off is the first-probe condition; it is not completion of the final charging goal.

Actual pre-userspace dependencies include PMIC fs_initcall (`pmic_mt6323.c:1898`), charger I2C probe, battery late_initcall (`battery_common.c:5331`), USB clock/PHY/controller setup, and the radio bootstrap late_initcall. Kernel initcalls run before `/init` (`K/init/main.c:865,964–976`). ADC polls are bounded in the reviewed new helper, but they still acquire PMIC/I2C mutexes. The inherited battery probe also dereferences `cdev_alloc()` without checking it (`battery_common.c:4601`), an allocation-failure panic path. These are concrete reasons the userspace timer cannot cover every early failure; no such failure was observed on a device here.

The independent deadline is a separate early-init root/recovery service, launched before ueventd and before the collection service. Its absolute CLOCK_MONOTONIC sleep is independent of the collector's 20-second sleep and sysfs stalls. AArch64 syscall numbers and structures match this 4.9 tree, including clock 113/115 and reboot 142. The label query is syscall 9 (`lgetxattr`), appropriate for the regular immutable shell endpoint. Failures of clock/sleep cause an early reboot attempt. The timer requests RESTART with no recovery argument.

But `K/kernel/reboot.c:68–73,214–224` runs blocking reboot notifiers and `device_shutdown()` before machine restart. BQ shutdown takes its mutex, does checked I2C disable and waits for delayed work (`bq25896.c:234–245`); battery shutdown takes `bat_mutex` before its bounded polling loop (`battery_common.c:4953–4983`). A wedged bus/lock can prevent reset. An error-returning syscall causes init to restart the deadline service and begin another 120-second interval. Therefore 120 seconds is a requested deadline after service start, not a guaranteed boot-to-stock bound.

The captured watchdog normal restart path does not explicitly clear recovery selection (`K/drivers/watchdog/mtk_wdt.c:196–269`); PMIC initialization clears LPRST, a different RTC state. The programmatic recovery audit's one-shot RTC concern remains. Config `KPD_PMIC_LPRST_TD=2` maps to nominal 14 seconds (`K/drivers/input/keyboard/mediatek/Kconfig:53–58`), and one-key reset is enabled in both modes. No 4.9 long-press or normal-return qualification exists. The proven stock five-second hold is not proof of the new kernel's behavior.

## Initrd precedence, USB and security

`K/arch/arm64/kernel/setup.c:256–258` scans FDT before early parameters; `K/arch/arm64/mm/init.c:63–77` overwrites initrd start/end from `initrd=`. Actual config is FROM_BOOTLOADER with EXTEND/FORCE unset. Its fallback CONFIG_CMDLINE contains no initrd override. The isolated board DTS removes the old 2 MiB argument. Both final input command lines agree, so no stale override is present in the reviewed kernel/header/DT inputs.

The exact saved LK copies match each other; their string data contains the initrd-property names. This review did **not** establish the exact LK append/fixup/relocation path or final x0/DT contents. Absence of a literal `initrd=` string in LK is not proof against dynamically generated overrides. The correct host image must not be promoted to proof that locked LK transfers/skips the MTK wrapper or hands these exact bounds to 4.9. Observe the actual `/proc/cmdline` after any supervised success; failure before userspace remains a possible test outcome.

Actual config has `USB_MTK_HDRC`, `USB_F_FS`, `USB_CONFIGFS`, `USB_CONFIGFS_F_FS`, AIO, futex/epoll/eventfd and SELinux enabled. Upstream `USB_MUSB_HDRC=n` is not a missing-driver defect: this tree uses the MediaTek USB20 driver. `usb20/mt8163/usb20.c:1310` creates `musb-hdrc` with PLATFORM_DEVID_NONE; `musb_gadget.c:2478` registers it; `drivers/usb/gadget/udc/core.c:1153` uses the parent's device name. **musb-hdrc is the supported expected UDC name.**

The FunctionFS mount gives UID/GID 2000 and mode 0660 files, with traversable 0770 directories. Binding happens only on `sys.usb.ffs.ready=1`. Actual stock adbd disassembly opens endpoints and checks failures before its success branch at **0x422884–0x422888**, then sets that property to `1` at **0x422bc4–0x422bd4**. This is stronger than a string-presence check (`evidence/adbd-ffs-disassembly.txt`). It is still not a runtime USB enumeration or authentication test on 4.9.

The byte-identical reproduced policy adds only the eight explicit TE grants in `B/probe/policy_patch.c`, with no permissive-map change. Additional binary-policy decisions cover recovery/adbd entrypoint and transitions, functionfs mount/file access, property socket/ffs property, adb key access and report publication. configfs's root genfs label is `configfs`. Adbd needs only search on the functionfs directory; read/open are denied but not needed for opening named endpoints. Mount-on is checked against the pre-mount device directory, not the mounted functionfs root. No blanket allow or enforcing bypass was found. UID2000/shell-context checks, a real regular shell_exec file, root-owned 0444 atomic report publication and denied adbd/shell tmpfs/block writes are coherent statically.

SDK37 host_init_verifier exit 0 is syntax evidence for that parser, not execution by the stock Android 7 init. Host libsepol evaluates TE/MLS/RBAC decisions, not target AVC/DAC/mount behavior. Local ASan mocks validate selected logic, not ARM syscall execution, scheduling or driver locks. The actual packaged adbd remains production/authenticated OEM bytes; the earlier stock-kernel authentication proof does not validate this new configfs boot path.

## Conditional continuation contract

1. Keep first 4.9 execution HELD while the user is away. No unattended GO follows from this review. Programmatic entry additionally needs the exact normal-return/RTC one-shot condition qualified by the parent; a source-only inference is insufficient.
2. Before a supervised attempt, resolve F1/F2 with a separate pinned profile and strict result interpretation, and handle F3 as explicit partial/failing diagnostics. Current r2 can be retained if the host contract handles these semantics; any helper/policy/init change creates a new candidate requiring new hashes/review. Retain the fixed p10 target, exclusive ownership, full candidate readback, exact stock inverse, and no retry after uncertain transport.
3. Require a fresh exact-stock preflight and same-run topology pin, verified full stock recovery backup/inverse availability, physical fallback present, and parent ownership released from any competing device work. Never select by generic serial, `-d`, or “only attached device.” Use the current verified transport ID and abort on ambiguity/change/error.
4. A diagnostic pass requires exact endpoint UID/domain, exact marker and terminal END framing, exact H5 serial token in cmdline, actual 4.9 identity, enforcing `1`, expected initrd token with no duplicate override, no unexpected persistent mount, and successful expected USB/UDC observations. Missing measurements are unavailable/failures, not fabricated success. Report transport, electrical/measurement results, normal stock return and full p10 restoration remain separate facts.
5. Stock return requires exact serial/product/device/fingerprint, SDK24 and boot_completed=1 on the freshly validated stock transport; restoration requires the entire 16,740,352-byte p10 readback hash `902b2f06a01cca574b4aa374e67c4e7f8f0ed53f6e6a55017b6d96351f0f1f20`. A normal deadline return does not prove an inverse write occurred.

The supplied earlier stock-control and explicit-inverse runtime receipts support stock-kernel changed-ramdisk execution, authenticated endpoint execution, one observed deadline return, and full stock recovery restoration/inverse readback. They explicitly do not prove 4.9 boot, its power-key fallback, or a failed-kernel rescue. The repaired stock report candidate remains unflashed. The ongoing full-system backup and independent internal-data/full-image qualifications do not waive these gates. Full OS flashing remains blocked on the parent's independent rescue, complete images and runtime/hardware acceptance.
