# MT8163 radio implementation handoff

The missing Linux 4.9 radio transport now has a concrete, fully linked ARM64 implementation. The final isolated build produced `Image.gz-dtb` successfully with WMT/STP, BTIF integration, `/dev/stpbt`, and the complete ASUS gen2 AHB WLAN driver. The matching loader/resident server also builds as an ARM64 static executable. This resolves the earlier “transport sources/symbols absent” condition. It does **not** establish successful hardware operation, an Android product build, or a persistent end-user radio experience yet.

## Implemented kernel behavior

The port retains the ASUS CONSYS_8163 command engine, STP framing and sleep/wake engine, BT character transport, WLAN MAC/management code, cfg80211 operations, and MT8163 AHB/PDMA implementation. The existing 4.9 BTIF driver and `connadp` remain in place. The old `common_detect` implementations are not linked; some original headers remain import inputs. This is not a set of feature defines or success stubs.

`CONFIG_ASUS_P00A_RADIO=y` adds one late-init bootstrap that registers `/dev/wmtdetect`. It does not start WMT threads, open firmware, or power a radio at kernel boot. The root-only loader uses the existing scalar `GET_SOC_CHIP_ID` and `DO_MODULE_INIT` ioctls after vendor/data mounts. Initialization is serialized and idempotent after success. A partial initialization failure is retained and returned, preventing duplicate registrations/threads on retry; recovery from that failure requires a new boot.

The original WMT init then reads `/vendor/firmware/WMT_SOC.cfg`, registers BT/Wi-Fi transport nodes and WLAN callbacks, and returns. Firmware reads use the 4.9 `kernel_read` interface. The old credential modification and cross-call address-limit manipulation are removed. WMT config parsing has explicit room for its terminating NUL. Internal ARM64 operation-pointer conversions use pointer-width storage.

The board power path uses the existing runtime-PM scpsys connection domain, MT6323 regulator supplies, and TOPRGU reset controller. MCU reset remains asserted through domain power-up and chip-ID polling, then deasserts at the original sequence point. Regulator, PMIC, reset and domain failures propagate; partial enable operations unwind. Co-clock mode retains the ASUS VCN28 distinction. BT and Wi-Fi share the ASUS VCN33_BT route with independent, idempotent ownership. No pad-battery, charger, SOC, thermal policy or DT charging opt-in is changed. Firmware/rail sequencing and timing still require physical validation.

The existing `connadp` owns the reserved EMI allocation. The imported implementation validates its size and maps the existing reservation instead of registering a competing reserved-memory owner. Its thermal callback uses the existing platform bridge. The transport build has no undefined or duplicate radio symbols.

The cfg80211 port supplies 4.9 scan-info structures, bands, station filled bits, vendor-event arguments, disconnection origin and scheduled-scan plans. Firmware scan intervals are converted from seconds to milliseconds and unsupported multi-plan/oversized intervals are rejected. Removed `last_rx` accesses are gone. The old IPv6-as-IPv4 address casts are replaced with typed, locked address-list reads for suspend. WLAN reads its entire existing 512-byte device record as one snapshot before translating fields; missing data, invalid MAC or invalid transmit-power flag fails startup instead of selecting invented identity/calibration.

## Loader and firmware protocol

`p00a-wmt --load` initializes through `/dev/wmtdetect`. `--serve` holds the WMT endpoint, verifies chip ID, sets real BTIF/FM-COMM HIF mode `0x23`, and polls kernel commands. It does not issue the upstream openmttools loopback power-on ioctl. Wi-Fi's first actual power request or BT's real open triggers WMT firmware download.

For `srh_patch`, the server queries actual chip/hardware/ROM information, reads candidate headers, verifies the ROM version, total count, unique contiguous sequence numbers, bounds and path length, and publishes all metadata only after validation. Every ioctl result is checked. The ASUS files encode **sequence 1 in `ROMv2_lm_patch_1_1_hdr.bin` and sequence 2 in `_1_0_hdr.bin`**. Filename sorting is not the protocol. Full `/vendor/firmware/...` paths and header-derived addresses are submitted. The kernel checks sequence bounds/duplicates and commits pointer/count only when complete. Only successful handling gets `ok`; missing patches, ioctl failure, UART baud/open commands or unknown operations produce errors.

The two ROM patches, `WIFI_RAM_CODE_8163` and the exact ASUS `WMT_SOC.cfg` remain the firmware inputs from connectivity-base.mk. Analog die/ROM identity is queried, not inferred from historical MT6628/FM/GPS names. No calibration data is a firmware-bundle input.

## Bluetooth ABI and calibration

The exact stock ioctl `0xc001b001` now invokes the real WMT/STP PSM enable/disable operation. Only scalar 0/1 is accepted; unready transport and transition errors propagate. The distinct ELF32 pointer-width HW/FW ioctls retain compat translation. Unsupported ioctls are errors.

The legacy library imports only `NVM_GetFileDesc` and `NVM_CloseFileDesc` from libnvram. Disassembly proves a 12-byte by-value descriptor, LID 1, one 64-byte record and read=1 for initialization. The second call requests a BDADDR write; the provider explicitly returns EOPNOTSUPP for that path. `libbtcal` reads the existing `/data/nvram/APCFG/APRDEB/BT_Addr` without fstab APIs, partitions, record creation or writable descriptors. It rejects short files, symlinks, invalid addresses and the captured library's built-in MT8163 default address.

The legacy caller falls back to built-in calibration when a required read fails. Consequently the provider **terminates the HAL on required-read failure**, before that fallback executes. This deliberate fail-stop behavior is a limitation to review, not a claim of graceful recovery. The optional HAL service is oneshot and gated by successful record preparation. The provider's host tests cover record and unsupported-write behavior; its ELF32 Android build and live binary interaction remain untested.

Only the captured `libbluetooth_mtk.so` dependency is redirected from `libnvram.so` to `libbtcal.so`; the global vendor libnvram is untouched. Two property strings are scoped to `vendor.p00a.chipid` and `vendor.p00a.btcal`. Chip ID is published after the driver's query; record readiness is published only after actual validation. No global `service.nvram_init=Ready` spoof is installed. The private HIDL address file is derived on-device from that same existing record, never from a generated address. Stock encrypted-data migration and availability of those existing records remain parent-owned gates.

## Exact apply and Android integration order

1. Start from committed kernel `717bb3c9e13ce573cfdd2dda856debd27a0fa17f`. Apply the battery-gauge prerequisite and main-battery-SOC changes in their documented order. This radio fixture deliberately did not apply or rebuild those later parent changes.
2. Preflight with `scripts/apply.py`; apply `0001-import-asus-mt8163-radio.patch`, then `0002-wire-mt8163-radio-kbuild.patch`. Only connectivity/Kconfig and connectivity/Makefile modify existing files. No `connadp` source file is changed by these patches, so never overwrite a parent's adapter with this spike's copied overlay. Keep the existing adapter object exactly once; do not add old common_detect stubs or the abstract WMT export layer. Any separate parent adapter change needs a combined symbol/link review.
3. In the actual output config enable `ASUS_P00A_RADIO`, `MTK_COMBO`, `MTK_COMBO_CHIP_CONSYS_8163`, `MTK_COMBO_BT`, `MTK_COMBO_WIFI`, `MTK_BTIF`, `CFG80211`, `PM`, `PM_GENERIC_DOMAINS`, `RESET_CONTROLLER`, `MTK_EMI_MPU`, `PM_WAKELOCKS` and `REGULATOR_MT6323`. These are built-ins (`y`). CRC16/CRC32/zlib are selected. Retain the parent's BPF/configfs/battery/other config choices and charging inhibition. Run olddefconfig and inspect the resolved output, then build with max `-j2`.
4. Merge `staged/device/asus/p00a/radio` into the reviewed product and inherit radio.mk plus the earlier connectivity-base.mk and wifi-sta-trial.mk/BoardConfig-connectivity.mk. Replace the existing wificond.rc with the staged disabled version, based on committed wificond `fefad78738af9d9753bb0acbafcf458691f8627c`; do not install duplicate service declarations. The source-built loader publishes readiness after real success. Wi-Fi activation waits for the resident server, powers through `/dev/wmtWifi`, verifies wlan0/phy80211, then starts wificond. No unsupported IWifi vendor HAL is declared. Current AIDL supplicant/nl80211 and lib_driver_cmd_p00a remain the STA route.
5. Merge the ueventd fragment and policy/property/file contexts. Add the policy directory to the board policy inputs, reconcile existing labels, and run full SELinux/init verification. These policy inputs have **not** been compiled against the full product. No permissive domain, ELF-check bypass or generic filesystem grant is supplied. Device-local NVRAM labels/permissions must permit the exact readers without making records public.
6. For Bluetooth, inherit bluetooth.mk, use the earlier source-built ELF32 HIDL 1.1 bridge and the scoped two-library inputs, and retain strict ELF dependency checks. Do not install the old bluetooth.default.so or an unrelated libbt-vendor. Merge its VINTF fragment once. The ro.bt.bdaddr_path property refers to the private derived address file, not an address value.
7. The staged init defaults do not activate radios. After integration/calibration review, select persistent `persist.vendor.p00a.radio.enable=1` for WLAN and/or `persist.vendor.p00a.bluetooth.enable=1` for BT and reboot the reviewed image. Each post-fs-data trigger starts the same idempotent loader. These are future integration instructions, not operations performed here.

The initial WLAN route retains wlan0 across framework toggles because wificond creates a client interface before starting supplicant. Full WLAN rail-off policy, power consumption, suspend/resume, AP/P2P and modern nl80211 feature coverage are runtime follow-ups; the STA path is the supported integration target here.

## Compiler evidence and checks

All work used `/srv/android/asus-radio-kernel-port`; no active product/main-kernel input or output was modified. The fixture was created with `git archive` of the pinned commit, configured from its committed asus_p00a_defconfig plus the radio options, and built with Ubuntu AArch64 GCC 13.3.0 at `-j2`. Final `logs/radio-r14.exit`, `full-r3.exit` and `userspace-build.exit` are zero. Logs, config, System.map, linked connectivity object and image are copied under `evidence/linux-build`. `compiler-input-sha256.json` matches all 246 delivered kernel files. The linker reports the inherited vmlinux RWX LOAD-segment warning; this successful build is not warning-free or a security certification.

The linked map contains real WMT ioctl/function-on, STP send, BT open, WLAN probe, bootstrap and power-control functions. `/dev/wmtdetect`, `/dev/stpwmt`, `/dev/stpbt`, `/dev/wmtWifi`, and later nl80211/wlan0 are the interfaces. **There are no radio .ko artifacts or modules.load order**; built-ins initialize via the loader.

`p00a-wmt-arm64` is a static GNU/Linux AArch64 executable (minimum ELF ABI Linux 3.7) built from the supplied source. The Linux host version returns failures for missing firmware/device context and invalid commands. This is actual target compiler evidence, **not a Bionic/Soong, HIDL, SELinux or physical Android execution result**. Android.bp is the normal product build path.

`python3 scripts/verify.py` passes 815 checks: exact patch replay/idempotence/conflict rejection, file/evidence hashes, final linked symbols/config, 13 protocol scenarios with ASan/UBSan and publication-failure injection, eight read-only BT-record scenarios, and exact production power-transition bodies against simulated failure-capable regulator/reset/PMIC/domain primitives. Tests do not emulate RF hardware or establish calibration accuracy.
