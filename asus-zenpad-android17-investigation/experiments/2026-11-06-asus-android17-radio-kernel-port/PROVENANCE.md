# Provenance and data boundary

The imported kernel implementation retains ASUS/MediaTek GPL source notices and the original licence copies under `sourceinputs`. ASUS release: `Kernel_V4_7_0.zip`, archive SHA256 `d8b9d77a7e8b5151c2b68c96e784842a25b167cf8a7044188e7044a5fdbcd41c`; see `evidence/source-provenance.json` and `source-manifest.json`. The new/changed kernel code is GPL-2.0-only.

The fixture was extracted from committed kernel `717bb3c9e13ce573cfdd2dda856debd27a0fa17f`. `sourceinputs/kernel-base-717bb3c9` is a fresh archive of that commit's connectivity subtree. Its files match the earlier bounded 4.9 snapshot exactly. The imported code uses the existing BTIF/connadp/power/reset/MT6323 implementations; no main kernel source or output was modified.

The firmware command protocol was developed from the supplied ASUS implementation and Dahrkael's MIT openmttools, revision `ef35f769d211a2942a6783410b58bd824dd363f9`. Original files and MIT licence are retained in `sourceinputs/openmttools`; per-file URLs/hashes are in `evidence/openmttools-provenance.json`. New userspace code is MIT licensed and retains attribution. It replaces the upstream unchecked ioctl handling and loopback power thread with validated metadata and an on-demand resident command server.

The four firmware/config files and two Bluetooth libraries are reused generic proprietary ASUS/MediaTek software from the earlier connectivity spike. Their capture history and distribution restrictions remain those in `../2026-11-06-asus-android17-connectivity/PROVENANCE.md`. They are not relicensed as MIT. Device ownership does not establish redistribution rights. Do not publish the blob-containing bundle without appropriate rights. Firmware hashes are in `evidence/firmware-manifest.json`; library input/output hashes and exact changed byte ranges are in `evidence/bt-record-abi.json`.

The Bluetooth adaptation changes a DT_NEEDED string and two property-name strings in non-executable sections. All executable code is retained. The captured binary's actual AAPCS calls establish the 12-byte NVM descriptor, LID 1, record size 64, count 1, read/write conventions and fallback behavior. The public header at https://github.com/andr3jx/MTK6577/blob/master/mediatek/source/external/nvram/libnvram/libnvram.h was used only to cross-reference field names; none of its implementation was copied. The independently written provider reads the existing record and rejects writes.

No real MAC/BDADDR, calibration file, user network, password or private key is included. Record tests generate synthetic fixtures in temporary directories and delete them. The runtime BT preparation code derives the bridge's private address file from the existing record entirely on-device; it was not executed. Missing records remain a runtime gate, with no manufactured defaults or automatic partition extraction.
