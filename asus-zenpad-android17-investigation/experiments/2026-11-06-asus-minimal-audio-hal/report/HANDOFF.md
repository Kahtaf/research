# Parent handoff — bounded source implementation complete, audio activation blocked

This stage implements a real tinyalsa C primary audio HAL with genuine SDK37 headers, Bionic link interfaces and current HIDL wrapper packaging. It **does not deliver working speaker or microphone yet**. Both routes remain compile-time unqualified (`src/routes.c`), `init_check` and stream opens return `-ENODEV`, and the product fragment intentionally refuses integration unless a future reviewed route revision is qualified. This is the authorized transport/core fallback, not a null HAL or a hardware-success simulation.

## Delivered and verified

- C HAL module API0.1/device API2.0, loader name `audio.primary.mt8163`, ARM64. Real SDK37 `android.hardware.audio@7.1-impl`, `android.hardware.audio.effect@7.0-impl` and `android.hardware.audio.service` are referenced by their existing module names. Board fragment selects the genuine service's64-bit variant. No wrapper/Android7 library is replaced.
- PCM open/config/prepare, read/write, standby, scalar enum route validation, explicit on/off plans, partial-transfer accounting, error propagation and shutdown-fault latch. Fixed48kHz S16_LE; stereo speaker/mono mic profiles;480-frame periods×4. No simultaneous capture/playback. No arbitrary mixer RPC, activation property, calibration reader or factory default writer.
- Actual serial SDK37 ARM64 compilation and `--no-undefined` links for the HAL and source-built `libtinyalsav2.so`, capped to one CPU and1GiB address space in `/srv/android/asus-minimal-audio-hal-20261106/out`. No Ninja, active-out mutation or build management. Link inputs use genuine vendor Bionic **symbol stubs** emitted by the current SDK37 build and its real crtbegin/crtend; these are correct link interfaces, not a runtime test. No Bionic stubs are supplied for installation.
- **58 transport assertions** using injected tinyalsa boundary calls, compiled against the real v2 header with ASan+UBSan on the Mac; **28 native host HAL-contract assertions** compiled against actual SDK37 HAL headers on the builder. These prove software behavior, not Android process startup or physical sound.
- Policy XML validates against captured SDK37 audio7.1 XSD, including volumes XInclude. Actual `assemble_vintf` and `host_init_verifier` pass. Readelf receipts record ARM64, HMI export, SONAME, DT_NEEDED and undefined symbols. Parent still must test the real installed HIDL wrapper/service dependency closure and full product VINTF compatibility.
- No SELinux rule is added. The available `secilc` was attempted on independently copied existing platform/vendor policy with neverallows enabled; it hit the explicit45-second bound and was killed by the runner. **No full neverallow pass is claimed.** `sepolicy-analyze` is absent. Exact limitation is in `evidence/policy-attempts.json`.
