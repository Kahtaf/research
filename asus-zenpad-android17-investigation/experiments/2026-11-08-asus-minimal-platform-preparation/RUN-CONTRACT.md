# RAM PID1 source contract

`source/ram_pid1.c` and `source/run_identity.h` are the only helper design. No helper binary exists. Run UUID: `a60fca94-e760-4ce5-a790-5c9a818ce406`.

The future initramfs needs only a static `/init`, RAM-root directories `/dev` and `/proc`, and optionally the `/dev/kmsg` character node (major 1, minor 11). PID1 creates those directories/node if needed and mounts only proc with nosuid/nodev/noexec. There is no sysfs, udev, devtmpfs requirement, USB/SD reporter, storage mount or block-device write. All observations go through ordinary `/dev/kmsg` into the calibrated retained text writer, with `console=null`. No strict sparse admission filter is present.

1. Report entry and actual `uname` values. Verify PID 1, `sched_getscheduler()==SCHED_OTHER`, `sched_getparam().sched_priority==0`, nice 0 and one online CPU. No scheduling setters or FIFO policy.
2. Report compute start once. Perform exactly 2,000,000 volatile unsigned iterations: 32-bit LCG state `state = state * 1664525U + 1013904223U`, starting `0x12345678`; accumulate each state into a volatile unsigned 64-bit checksum. No clock reads, progress writes or kernel calls inside the compute loop. Report final state/checksum once and require state `0x2093acf8`, checksum `4296231513146560`.
3. Install a SIGALRM handler that only sets `volatile sig_atomic_t alarm_seen`. Block SIGALRM while setting each one-shot `ITIMER_REAL` alarm for nominal one second; use `sigsuspend` with SIGALRM atomically unblocked to wait. This avoids a lost-wakeup window. Other EINTRs do not count. Exactly five completed alarm waits are required.
4. Each cycle reports at most two records: before arming (CPU0 architecture timer IRQ count and CLOCK_MONOTONIC), then after the actual SIGALRM wait returns (new IRQ count and monotonic observation). Read `/proc/interrupts` directly, requiring CPU0, no CPU1, and one architecture timer IRQ line. Require IRQ count and monotonic observation to increase on every cycle. No clock rate rescaling, walltime estimate or busy clock loop.
5. Report `success operation=five-timer-returns`, then call normal `reboot(RB_AUTOBOOT)`. A clear syscall, scheduler, checksum, IRQ or timer-observation error reports the failing operation/errno and requests the same normal reboot. If reboot returns, emit one error and pause. If a kernel syscall/compute/timer path stalls, no timer bound or automatic fallback is guaranteed. Owner accepts eventual manual Power fallback.

Five timer returns are functional evidence, not calibrated five seconds. A retained write returning does not independently prove physical retention. A missing tag, incomplete record sequence or saturated retained buffer remains incomplete/ambiguous, never a pass. The ancestor writer keeps initial text and freezes when full; the retained protection drivers can still produce logs.

A future trial's evidence target is one fresh entry identity, actual 4.9 uname, verified normal scheduler, exact compute result, all five timer-return records with increasing IRQ/monotonic observations, success/reboot request, then separately verified stock return. A helper success record alone does not prove stock return, sustained OS readiness, storage qualification or working physical protection. Negative/ambiguous outcome ends this coarse attempt for reassessment, with no automatic fine-grained variants.
