# One protection-preserving removal set

This is a substantially reduced consumer configuration with the existing vendor protection closure. A literal CPU/GIC/timer/RAM-only kernel is incompatible with that closure in this tree. The proposal does not remove CPUFreq, thermal, battery control, PMIC settings, watchdog or power-key/reset infrastructure to obtain a smaller result. Whether this retained closure is a sufficiently useful coarse experiment is the remaining parent review decision. Rejection means stop and seek the owner's Opus-first reassessment; no replacement configuration is prepared here.

| Area | Decision | Dependency fact and remaining work |
|---|---|---|
| CPU0, GIC, architecture timer, normal IRQ/preemption, RAM | Keep | `SMP=y`, `NR_CPUS=4`, `PREEMPT=y`, `HZ=250` and interrupt/timer configuration equal the ancestor. Arm64's `NR_CPUS` range starts at 2, so do not force an invalid UP configuration. Selected boot arguments `nr_cpus=1 maxcpus=1` limit possible and initially online CPUs; PID1 verifies one online CPU and CPU0 interrupt observations. |
| CPUFreq and CPU cooling | Keep | `mt_cpufreq_thermal_protect()` has its functional body under `CONFIG_CPU_FREQ`. Existing ELF shows `thermal_budget_notify → mt_cpufreq_thermal_protect → cpufreq_cpu_get / hps_set_cpu_num_limit / _mt_cpufreq_set`. Keep CPUFreq, its existing governors, virtual thermal, base power, regulators, thermal bindings and trips. |
| Base power, CPU_IDLE, SPM, HPS, PTP/DCM, GPU frequency support | Keep the bundled closure | `MACH_MT8163` selects `MTK_BASE_POWER`, `CPU_IDLE`, `CPU_IDLE_GOV_MTK` and scheduler accounting. Base-power Makefiles unconditionally bundle SPM, idle, PTP, CPUFreq, GPUFreq and HPS for MT8163. Removing the whole bundle removes CPU cooling dependencies. No new `nohlt`, idle-poll, clock-gating or frequency experiment. GPU rendering is removed; bundled frequency/protection code remains. |
| PMIC, regulators, AUXADC, I2C0/I2C1, thermal sensors | Keep | Preserve `MTK_PMIC`, PMIC wrap, MT6323/SYM827 rails, generic/board thermal, AUXADC and relevant DT nodes. Battery and PMIC thermal readers remain. No edits to autonomous trip bits, PMIC phase/control, regulator limits, hardware addresses or interrupt routing. |
| BQ25896 control and charge inhibition | Keep | BQ25896 DT node and configuration remain. `asus,allow-battery-charging` is absent. The existing `p00a_apply` verification/disable/control path and probe/shutdown behavior are byte-identical; no charging permission is added. Preserve the ancestor's existing hardware writes and inhibition behavior, with no new hardware-writing code. |
| Checked battery/SOC/diagnostic cluster | Keep: not independently removable here | `ASUS_P00A_MAIN_BATTERY_SOC` depends on `ASUS_P00A_BATTERY_DIAGNOSTIC`, which depends on BQ25896 and PMIC. `BAT_thread` uses the SOC branch to supply temperature to `mt_battery_thermal_check`, request charge through the existing permission gate, and avoid the legacy USB-ready wait. `mtktsbattery_get_temp` calls the diagnostic property reader in the existing ELF. Turning off these flags would select different control/thermal behavior, not merely delete diagnostics. |
| Battery notifications / power_supply work | Keep: no standalone removal switch | The retained BAT_thread emits USB/AC/battery notifications. There is no isolated notification Kconfig switch in the inspected boundary. Removing `POWER_SUPPLY` or smart battery removes control infrastructure. No uevent omission patch or runtime hook is carried forward. |
| USB host/gadget/OTG/reporters | Remove | USB class and MTK controller options resolve off, as do the standalone PHY/transceiver/dual-role options. Existing `battery_common.h` supplies conditional no-op connect/disconnect macros with MTK USB off; existing weak `is_usb_rdy()` returns true. No new stub is introduced. This fallback may permit the already-existing charger-detection work to run; charging permission remains absent. Both controller DT nodes disabled. No helper USB setup. |
| Watchdog, power-key, reset | Keep exact ancestor behavior | Generic watchdog core, MediaTek watchdog and kicker remain; keypad/PMIC long-press/reset and RTC remain. The ancestor's `mtk_wdt.c` registers at `arch_initcall`; its non-DOUGLAS/GIZA probe stops the bootloader watchdog before registration. It is not an armed autonomous timeout guarantee. This design does not change that entry-proven behavior or open/kick a watchdog in PID1. |
| Display/GPU/media/camera/audio | Remove consumer drivers | MTK framebuffer/LCM/backlight, rendering GPU, video/JPEG/camera/CMDQ/M4U/SMI consumer options, sound/media and audio consumers off. Clock providers (`audiosys`, `mmsys`, `imgsys`, vdec/venc clock nodes) remain untouched. Removing MTK LEDs also removes the display backlight cooler through its existing Makefile condition; CPU/battery/PMIC critical and shutdown paths remain. |
| Sensors/touch/network/storage | Remove consumer drivers | Sensor/touch/hall/radio/combo/Bluetooth/network, MMC, SCSI/ATA/MTD and mounted-storage filesystem classes resolve off. Keypad power-key path remains. I2C2 sensor/camera bus disabled; charger and VPROC buses stay enabled. Generic block infrastructure may remain, without a selected block-device reporter or storage mount. |
| Android default selector | Remove selector, preserve explicit keeper values | It force-selects framebuffer, networking and USB gadget features, so direct disabling alone did not resolve. Turn off `ANDROID_DEFAULT_SETTING` and retain the explicit ancestor keeper values. One initial resolution exposed these selects; one dependency correction produced the final warning-free configuration. This is one configuration, not alternative candidates. |
| Retained text / entry | Keep calibrated geometry and ordinary writer | Assembly/header/memory guards and normal `log_store → asus_retained_trace_write` unchanged. The calibrated minimum-header admission supports the physically observed 0xc0 layout. Existing two writer initialization markers remain as part of its early-to-linear-map integrity contract. Remove the five external setup/IRQ/time checkpoint calls from `init/main.c`; refresh entry identity. No strict sparse filter, hot/cold records, WENT/WRET, PMIC-phase/scheduler barriers, pwrap budget or battery omission is imported. |

`dt/status-manifest.json` lists all 99 exact node paths, grouped by class with their purpose. These paths were checked against the existing calibrated packaging-reference DTB, without compiling a new DTB. The source patch uses `&{/exact/path}` references: a wrong path must fail DT compilation rather than silently create a new node. Status edits touch only intended consumers, plus `/chosen/bootargs`. No memory, reservation, regulator, thermal, CPU, GIC, watchdog or timer node is disabled. `mt8163.dtsi` is unchanged.

The final configuration is `config/resolved.config`; every direct and derived difference is in `config/derived-changes.json` and the combined patch. Some orphan descriptive flags remain (for example the GPU version string, `LCM_SEND_CMD_IN_VIDEO`, and a WiFi DHCP option), but their class driver build gates are off. Their presence is not evidence that the removed device class runs.

The source pass covered 17 implementation bodies (including calibrated entry/writer and the two files needed to remove external checkpoints), plus directly relevant headers, Kconfig, DT and Makefiles. There was no kernel history audit, full-tree production source search or new ELF build. `evidence/08_freeze_design.json` binds selected source files to the copied ancestor. Existing linked evidence is ancestor-only and does not prove the unbuilt configuration links or preserves runtime bindings.

Unresolved limits are physical qualification of the preserved paths, liveness under the retained BAT/thermal/charger/SPM/HPS workload, normal reboot, and actual linked dependencies after the one future build. No observed result or source preservation qualifies hardware protection. No timer-derived availability guarantee is made.

Other ancestor infrastructure also remains: MD32 support, RTC/boot metadata, DRAM/EMI/DEVAPC, memory/ATF/last-PC facilities, generic security/Android IPC and generic kernel workers. This bounded pass does not claim a bare-core kernel or prove that each such facility is required for protection. They are not a fallback almost-full consumer configuration: the listed whole device classes are disabled. Further stripping of this vendor infrastructure would require another dependency decision, not an automatic continuation of this design. The parent review gate covers whether the demonstrated reduction is useful despite that residual work.
